Модель исполнения — это сердце любого движка регулярных выражений. Именно на этом этапе решается, как построенное дерево (AST) будет проверяться на реальном тексте.
Для стандарта POSIX выбор алгоритма критически важен: привычный поиск с возвратами здесь не подходит, поэтому используется недетерминированный конечный автомат (NFA) Томпсона.

Почему не подходит обычный Backtracking (поиск с возвратами)

Большинство современных языков (Python, JavaScript, PHP, Java) используют движки на базе алгоритма с возвратами. Такой движок идет по одной ветке шаблона, а при неудаче возвращается к последней развилке и пробует другой путь.
У этого подхода есть две критические проблемы для POSIX:
• Несоответствие правилу POSIX (Leftmost-Longest). Движок с возвратами останавливается на первом найденном совпадении. Например, на строке "aaaa" шаблон (a|aaaa) в Python вернет "a", потому что первая ветка сработала сразу. Стандарт POSIX требует проверить все возможные варианты и вернуть самый длинный — "aaaa".
• Экспоненциальное зависание (ReDoS). На шаблонах с вложенными повторениями (например, (a+)+b на строке "aaaaaaaaaaaaaaaaaac") backtracking начинает перебирать миллионы одинаковых комбинаций, что вешает программу на минуты или часы.

Как работает модель Томпсона (NFA)

Идея Кена Томпсона (1968 год) заключается в том, чтобы не угадывать путь и не возвращаться назад. Вместо этого движок ведет все возможные пути одновременно, двигаясь по входной строке строго слева направо, символ за символом.
Принцип работы строится на трех правилах:
• Состояния вместо дерева. Регулярное выражение превращается в граф состояний (или набор инструкций виртуальной машины). Переходы между состояниями бывают двух типов:
	• Символьные переходы — срабатывают, только если текущий символ текста совпадает с ожидаемым (например, буква 'a').
	• Пустые переходы (ε-переходы) — срабатывают мгновенно, без чтения символа из строки (используются для развилок |, циклов * и сохранения границ скобок).
• Параллельные «потоки» (Threads). В каждый момент времени у движка есть список активных состояний — назовем его CurrentList. Когда из текста читается очередной символ, движок проверяет его сразу для всех состояний из CurrentList. Те, что подошли, переходят в список для следующего символа — NextList.
• Дедупликация состояний. Если два разных пути привели автомат в одно и то же состояние на одном и том же символе текста, дубликат отбрасывается. Благодаря этому количество активных путей никогда не превышает количество элементов в самом шаблоне.

Почему эта модель идеальна для POSIX

Использование автомата Томпсона решает сразу все задачи стандарта:
• Гарантия самого длинного совпадения. Поскольку все ветки движутся по тексту синхронно, когда одна ветка доходит до конца шаблона (например, после первой 'a' в (a|aaaa)), движок запоминает этот успех, но не останавливается. Другая параллельная ветка продолжает идти до четвертой 'a' и перезаписывает результат как более длинный.
• Линейная скорость \(O(N \cdot M)\). Время работы зависит только от длины текста (N) и размера шаблона (M). Никакой хитрый текст не заставит движок зависнуть.
• Естественная работа с потоками данных. Текст читается строго по одному символу вперед без откатов назад, что позволяет применять движок даже к сетевым потокам или огромным файлам.

Главный нюанс при адаптации под POSIX

Классический автомат Томпсона просто отвечает на вопрос «совпало / не совпало» (true/false). Чтобы превратить его в полноценный POSIX-движок, модель нужно немного усложнить:
• Контекст у каждого потока. Каждый активный путь в списке CurrentList должен носить с собой маленький массив координат — где началось совпадение и где открывались/закрывались круглые скобки (...).
• Разрешение слияний. Когда два пути сходятся в одном состоянии на одном символе, нельзя отбрасывать дубликат вслепую. Нужно оставить тот путь, у которого по правилам POSIX выше приоритет (например, где первая группа захвата оказалась длиннее).
