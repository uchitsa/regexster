На Этапе 3 построенное синтаксическое дерево (AST) превращается в плоский массив команд для крошечной виртуальной машины. Это подход, описанный Рассом Коксом (Russ Cox) в его знаменитых статьях о регулярных выражениях. Вместо сложных графов в памяти вы получаете линейный список инструкций, по которому легко двигаться по индексам.

1. Набор инструкций (Опкоды)

Чтобы выразить любое регулярное выражение стандарта POSIX, достаточно спроектировать 7 базовых инструкций:
• CHAR c / CLASS set — проверяет текущий символ текста. Если символ совпал, поток переходит к следующей инструкции (pc + 1). Если нет — поток погибает.
• ANY — проверяет любой символ (точка .), обычно за исключением переноса строки \n.
• ANCHOR type — проверка границ (^ или $). Не потребляет символ текста, а лишь проверяет текущую позицию.
• JMP addr — безусловный переход на инструкцию с номером addr.
• SPLIT addr1, addr2 — разветвление. Создает два параллельных потока выполнения: один идет по адресу addr1, второй — по адресу addr2.
• SAVE slot — записывает текущий индекс символа в тексте в ячейку памяти потока с номером slot.
• MATCH — сигнализирует, что поток успешно дошел до конца шаблона.

2. Как узлы AST превращаются в инструкции

Компилятор обходит дерево (AST) рекурсивно и дописывает инструкции в общий список code. Для каждого типа узла есть строгий шаблон генерации:

Листья (CharNode, ClassNode, AnchorNode)

Просто добавляют одну соответствующую инструкцию в конец списка.

Конкатенация (ConcatNode(left, right))

Самый простой случай. Сначала компилируется левое поддерево, а сразу следом за ним — правое. Поток естественным образом пройдет через первое и перейдет ко второму.

Альтернатива (AltNode(left, right))

Чтобы выполнить либо left, либо right, нужно поставить развилку в начале и прыжок в конце первой ветки, чтобы она не «провалилась» во вторую:
text
L1: SPLIT L2, L3      # Разделяем поток на две ветки
L2: <код ветки left>
    JMP L4            # Если left прошла, перепрыгиваем right
L3: <код ветки right>
L4: ...               # Общее продолжение шаблона
Используйте код с осторожностью.

Группы захвата (GroupNode(id, child))

Каждой группе id выделяются две ячейки памяти: id * 2 для начала и id * 2 + 1 для конца. Весь шаблон целиком автоматически оборачивается в группу 0.
text
    SAVE (id * 2)     # Фиксируем старт группы
    <код child>
    SAVE (id * 2 + 1) # Фиксируем конец группы
Используйте код с осторожностью.

3. Компиляция квантификаторов (RepeatNode)

Повторения строятся с помощью комбинации SPLIT и JMP.

Ноль или более (A*)

Поток должен иметь выбор: либо зайти в тело A и повторить цикл, либо сразу пойти дальше.
text
L1: SPLIT L2, L3      # Влево — в цикл, вправо — на выход
L2: <код для A>
    JMP L1            # Возвращаемся к развилке для следующей итерации
L3: ...               # Выход из цикла
Используйте код с осторожностью.

Один или более (A+)

Отличается от * только тем, что первый проход по A обязателен, а развилка ставится в конце.
text
L1: <код для A>
    SPLIT L1, L2      # Повторить еще раз (на L1) или выйти (на L2)
L2: ...
Используйте код с осторожностью.

Ноль или один (A?)

text
    SPLIT L1, L2      # Выполнить A или пропустить
L1: <код для A>
L2: ...
Используйте код с осторожностью.

Интервалы (A{min, max})

В POSIX-движках интервалы проще и надежнее всего разворачивать на этапе компиляции, не усложняя саму виртуальную машину счетчиками:
• Сначала компилируются min обязательных копий <код для A>.
• Если max задан конкретным числом — дописываются (max - min) опциональных блоков, как для A?.
• Если max не ограничен ({min,}) — в конце дописывается один блок цикла A*.

4. Главная техническая задача: разрешение адресов (Backpatching)

При генерации инструкций SPLIT или JMP вы часто еще не знаете точный индекс целевой инструкции (например, L3 или L4), так как код внутри ветки еще не скомпилирован.
Эта проблема решается методом отложенной подстановки (Backpatching):
1. Когда вы создаете SPLIT L2, None, вы запоминаете индекс самой инструкции SPLIT в переменной split_idx.
2. Затем компилируете внутренний блок <код ветки>.
3. Когда блок готов, вы берете текущую длину списка инструкций len(code) и записываете это число в code[split_idx].arg2.
Когда байт-код готов, остаётся Этап 4: Исполнение на виртуальной машине. Готовы разобрать, как именно устроен цикл прохода по тексту, как защититься от бесконечных циклов на пустых переходах (вроде (a*)*) и как реализовать правило leftmost-longest?
